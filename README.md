# Battle City Inspired — расширенная версия на Canvas

Игровой проект в жанре battle city, написанный на чистом JavaScript без фреймворков. Три режима игры, система прокачки танков, экономика на монетах и защита базы от волн врагов.

Игра представляет собой мой процесс изучения HTML, CSS и JS. Множество очень странных решений (был даже div вместо span).

## Режимы игры

### PVP (Player vs Player)

Два танка на одном экране. Игроки собирают зелёные сферы для прокачки и монеты для увеличения счёта. С каждым уровнем танк становится быстрее, меньше (сложнее попасть), получает увеличенный боезапас. На 3-м уровне появляется пушка, на 7-м — самонаводящееся оружие. Попадание снижает HP, при нуле HP — понижение уровня; на первом уровне — смерть.

**Управление:**

-   Игрок 1: `WASD` — движение, `Q` — выстрел
-   Игрок 2: `Стрелки` — движение, `Shift` — выстрел

### Survival (выживание)

Кооперативный режим: два игрока защищают базу от волн фиолетовых врагов. С каждым уровнем враги становятся сильнее и появляются новые типы. Монеты — общая валюта для прокачки базы.

**Прокачка базы (клавиши):**

-   B — станция боеприпасов
-   H — медстанция
-   M — купить ящик патронов (если есть станция)
-   K — купить аптечку (если есть станция)
-   R — ремонт базы
-   U — улучшение базы (требует обе станции 4 уровня)

### PVE (Player vs Environment)

Режим в разработке — планируется бот-противник, повторяющий логику PVP.

## Стек

-   **JavaScript (ES6+)** — без фреймворков
-   **HTML5 Canvas** — рендеринг всей графики
-   **Web Audio API** — звуковые эффекты
-   **requestAnimationFrame** — игровой цикл

## Архитектура

Проект написан в одном файле, но логически разделён на блоки:

-   **Инициализация** — выбор режима, настройка обработчиков
-   **Ввод** — обработка клавиатуры и кнопок (мышь/тач)
-   **Игровой цикл** (`draw`) — обновление состояния и рендеринг
-   **Режимы** — отдельные ветки логики для PVP, Survival, PVE
-   **Сущности** — танки, пули, монеты, враги, станции

## Что бы я улучшил сейчас

Оглядываясь назад после нескольких лет опыта:

-   **Разбить на модули** — сейчас всё в одном файле, что затрудняет поддержку. Логично вынести `entities/`, `systems/`, `render/`.
-   **Использовать классы или фабрики** для танков, пуль, врагов — сейчас сущности описаны десятками отдельных переменных (`bulletx`, `bullety`, `bulletspeed` и т.д.), это тяжело масштабировать.
-   **Вынести конфигурацию** (скорости, урон, цены) в отдельный объект, а не мучаться с `if (level == 1) { speed = 175; ... }`.
-   ~~**Добавить Git** — проект писался до знакомства с git, история версий потеряна.~~
-   **Использовать TypeScript** — типы сильно помогли бы с таким количеством состояния.
